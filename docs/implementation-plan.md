# Implementation Plan

Phased delivery. Each phase has an exit criterion that is verifiable without guessing.

## Guiding principles

- Reuse `Npgsql.EntityFrameworkCore.PostgreSQL`; override the minimum number of services.
- Make correctness testable at SQL-generation time (string assertions), independent of a live
  DSQL cluster.
- No ADO.NET wrapping, no regex over SQL, no external tools. See [`design.md`](design.md) §3–4.
- Fail at model/SQL generation with actionable errors for unsupported features.

## Solution layout

```
Amazon.AuroraDsql.EntityFrameworkCore.sln
src/
  Amazon.AuroraDsql.EntityFrameworkCore/            # provider adapter
    Extensions/                                     # UseDsql(...) entry points
    Infrastructure/                                 # options extension + builder
    Migrations/                                     # SQL generator, history repository, executor
    Storage/                                        # connection, transaction factory
    Metadata/                                       # conventions, model validator, type mapping
    Update/                                         # execution strategy
tests/
  Amazon.AuroraDsql.EntityFrameworkCore.Tests/      # unit tests, SQL string assertions
  Amazon.AuroraDsql.EntityFrameworkCore.IntegrationTests/  # requires a DSQL cluster
examples/
  InventoryApi/                                     # sample app (mirrors the AWS example for parity)
```

## Phase 0 — Scaffold

- [ ] Create solution and projects, target `net8.0` (align with the chosen EF Core major).
- [ ] Reference `Npgsql.EntityFrameworkCore.PostgreSQL` and `Amazon.AuroraDsql.Npgsql`.
- [ ] Enable nullable, implicit usings, `TreatWarningsAsErrors`, deterministic builds.
- [ ] Add `.editorconfig`, CI workflow (build + unit tests).

**Exit:** `dotnet build` and `dotnet test` succeed on an empty solution.

## Phase 1 — Options and entry point

- [ ] `DsqlDbContextOptionsBuilder` (identity cache size, retry count/delay, feature toggles).
- [ ] `DsqlOptionsExtension : IDbContextOptionsExtension` with correct
      `DbContextOptionsExtensionInfo` (hash, `ShouldUseSameServiceProvider`, debug info).
- [ ] `UseDsql(DbContextOptionsBuilder, DsqlDataSource | IServiceProvider, Action<...>)`
      overloads and generic `DbContextOptionsBuilder<TContext>` variants.
- [ ] Pass the connector's `NpgsqlDataSource` directly to `UseNpgsql(...)`.

**Exit:** a `DbContext` configured with `UseDsql` can open a connection and run a trivial query
against a DSQL cluster.

## Phase 2 — Model conventions and validation

- [ ] Model-finalizing convention: UUID PKs default to `gen_random_uuid()`;
      optional `long` identity PKs use `GENERATED BY DEFAULT AS IDENTITY (CACHE n)` with
      `n == 1 || n >= 65536`.
- [ ] Model validator rejecting unsupported features: enums/`CREATE TYPE`, ranges, arrays as
      stored columns, `hstore`, `tsvector`, geometry/PostGIS, unsupported extensions.
- [ ] Decimal precision convention aligned with DSQL's `numeric(18,6)` default.

**Exit:** unit tests assert conventions and that unsupported models throw with clear messages.

## Phase 3 — Migrations

- [ ] `DsqlMigrationsSqlGenerator : NpgsqlMigrationsSqlGenerator`
      - `CreateIndexOperation` → `CREATE INDEX ASYNC` (reject `CONCURRENTLY`).
      - `ForeignKeyConstraint` → `NOT VALID` + `ALTER TABLE ASYNC ... VALIDATE CONSTRAINT`.
      - Deterministic `IF NOT EXISTS` / `IF EXISTS` per operation.
      - Reject unsupported operations.
- [ ] `DsqlHistoryRepository : NpgsqlHistoryRepository` without `LOCK TABLE ... ACCESS EXCLUSIVE`.
- [ ] `DsqlMigrationCommandExecutor` running one command per transaction (1 DDL/tx).

**Exit:** `dotnet ef migrations add` produces DSQL-valid SQL; `dotnet ef database update`
applies it against a cluster, including a re-run after a simulated partial failure.

## Phase 4 — Transactions and runtime SQL

- [ ] `DsqlRelationalConnection` forcing the DSQL isolation level (never emits
      `SET TRANSACTION ISOLATION LEVEL`).
- [ ] `DsqlRelationalTransactionFactory` returning a transaction with `SupportsSavepoints => false`.
- [ ] Register overrides with `services.Replace(...)` in `ApplyServices`.

**Exit:** `SaveChanges` inside an explicit transaction emits no `SAVEPOINT`; captured SQL
contains no `SET TRANSACTION ISOLATION LEVEL`.

## Phase 5 — OCC retry

- [ ] `DsqlExecutionStrategy` retrying `SQLSTATE 40001` with exponential backoff + jitter.
- [ ] `ExecuteInTransactionAsync` helper for explicit transactions, clearing tracked state
      between attempts.
- [ ] Wire retry options from `DsqlDbContextOptionsBuilder`.

**Exit:** an induced serialization conflict is retried transparently and ultimately succeeds.

## Phase 6 — Testing

- [ ] Unit tests: SQL generation snapshots for all overridden operations.
- [ ] Integration tests against a real DSQL cluster (env: `CLUSTER_ENDPOINT` + AWS creds):
      CRUD, navigation properties, batch `SaveChanges`, explicit transactions, migrations,
      OCC retry.
- [ ] Port/execute a representative subset of the `efcore.pg` functional test suite against
      DSQL to find gaps.

**Exit:** integration suite green on DSQL; documented list of known-unsupported scenarios.

## Phase 7 — Packaging and docs

- [ ] NuGet metadata, README usage section, versioning aligned with EF Core major.
- [ ] CI publishing workflow (manual approval gate).
- [ ] Decide on an OSS license (blocked on owner decision; currently TBD).

**Exit:** package installable from NuGet and usable following the README alone.

## Risks

| Risk | Mitigation |
| --- | --- |
| `efcore.pg` internals change between majors | Pin to major; keep overrides small; track `EF1001` usages explicitly |
| DSQL feature set changes | Centralize assumptions in the compatibility layer; integration tests catch drift |
| 3,000-row limit not enforceable provider-side | Document clearly; surface server error with guidance; revisit if needed |
| Scaffolding unsupported by DSQL catalogs | Mark database-first as unsupported until verified |
